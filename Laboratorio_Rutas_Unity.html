1. Del escenario al grafo

Un NPC necesita decidir cómo llegar a un objetivo evitando obstáculos. En lugar de explorar infinitas posiciones reales, representamos el espacio mediante un grafo G=(V,E): los vértices son posiciones o regiones transitables y las aristas son desplazamientos permitidos. Cada arista puede tener un coste.

En un grid, cada celda se identifica por (x,z) en Unity; Y representa la altura. Una matriz bool[,] indica transitabilidad. Con cuatro vecinos se permiten desplazamientos ortogonales; con ocho también diagonales. Un laberinto 3D con suelo plano sigue siendo un problema de navegación 2D sobre XZ.

DFS: profundidad

Explora una rama hasta agotarla y retrocede. Marca los visitados para evitar ciclos. Útil para generación de laberintos y comprobación de conectividad. En un laberinto perfecto existe una única ruta simple entre dos celdas; en un grafo general DFS no garantiza la mínima. Para garantizarla con DFS habría que explorar alternativas y comparar longitudes, con un coste potencialmente exponencial.

BFS: anchura

Explora todos los nodos a distancia 1, después a distancia 2, etc. Al descubrir un nodo se registra su padre. En un grafo no ponderado DFS y BFS tienen complejidad O(V+E) y memoria O(V) con visitados.

A*: búsqueda informada

g(n): coste acumulado real desde el origen. h(n): estimación del coste restante. f(n)=g(n)+h(n). Se extrae el nodo de menor f de OPEN, se examinan sus vecinos y se actualiza el padre si aparece una ruta más barata. CLOSED contiene los nodos ya expandidos. Se termina al extraer la meta, no simplemente al descubrirla.

Manhattan: h=|dx|+|dz| para cuatro vecinos de coste 1. Octil: h=14·min(dx,dz)+10·|dx−dz| para ocho vecinos de costes 10 y 14. Con h=0, A* equivale a Dijkstra. Una heurística admisible no sobreestima; una consistente cumple h(n) ≤ coste(n,m)+h(m), permitiendo cerrar nodos sin reabrirlos. Una heurística arbitraria puede perder optimalidad.

No confundir longitud en pasos, coste de movimiento y número de nodos explorados. A* no es siempre más rápido: depende del mapa, la heurística y la implementación.

Reconstrucción

Desde la meta seguimos parent hasta el origen y luego invertimos la lista. Si la frontera queda vacía sin llegar a la meta, no existe ruta.

3. Navegación en Unity

Hay dos enfoques: programar nuestro propio grid (objetivo de la tarea) o usar el sistema de navegación de Unity para un agente. No son equivalentes.

Esquema conceptual, no captura de Unity. El recorrido real depende de la geometría y el agente.

Cómo se construye una NavMesh

  1. Se recopila geometría de la escena (mallas o colliders según configuración).
  2. El proceso de bake rasteriza la geometría en una representación voxelizada; considera altura, radio, pendiente máxima y altura de escalón del agente.
  3. Se identifican regiones transitables y se construye una malla de polígonos conectados. Los obstáculos y espacios estrechos pueden excluirse.
  4. A* busca una secuencia de polígonos conectados, considerando costes de áreas. El sistema calcula una trayectoria dentro del corredor y el agente sigue la ruta con evitación local.

El tamaño de voxel afecta a precisión y coste de construcción. Un grid demasiado grueso puede perder pasillos; uno demasiado fino aumenta memoria y trabajo. La NavMesh permite representar rampas y superficies irregulares sin obligar al agente a caminar de centro a centro de cuadrados.

Práctica guiada: NavMeshAgent

  1. Crea una escena con un Plane, varios cubos y una Capsule como agente.
  2. Instala AI Navigation desde Window → Package Manager si no está disponible.
  3. Añade NavMeshSurface a un objeto, configura geometría y tipo de agente y pulsa Bake.
  4. Añade NavMeshAgent a la cápsula. Coloca un objeto vacío sobre una zona transitable como destino.
  5. Adjunta este script y asigna el destino en el Inspector. Ejecuta y observa el recorrido.
using UnityEngine;
using UnityEngine.AI;
public class IrAlDestino : MonoBehaviour {
    public Transform destino;
    void Start() {
        GetComponent<NavMeshAgent>().SetDestination(destino.position);
    }
}

SetDestination solicita el cálculo de una ruta; pathPending indica si está pendiente y pathStatus permite distinguir ruta completa, parcial o inválida. NavMeshObstacle con carving puede modificar la zona navegable. NavMeshLink conecta superficies separadas. Los nombres de menús pueden variar según versión.

Documentación oficial: Navigation System · Funcionamiento interno · NavMeshAgent.

4. Implementación propia en C#

El siguiente núcleo independiente recibe una matriz de transitabilidad, origen y destino. Usa cuatro vecinos, coste 1 y Manhattan. Devuelve una lista vacía si no hay ruta. No sustituye la escena ni la selección de casillas de la tarea.

using System.Collections.Generic;
using UnityEngine;
public static class BusquedaGrid {
    public static List<Vector2Int> Buscar(bool[,] libre,
        Vector2Int inicio, Vector2Int meta, string algoritmo) {
        int w=libre.GetLength(0), h=libre.GetLength(1);
        bool Valido(Vector2Int p) => p.x>=0 && p.y>=0 &&
            p.x<w && p.y<h && libre[p.x,p.y];
        int H(Vector2Int p) => Mathf.Abs(p.x-meta.x)+Mathf.Abs(p.y-meta.y);
        var ruta=new List<Vector2Int>();
        if(!Valido(inicio)||!Valido(meta)) return ruta;
        var open=new List<Vector2Int>{inicio};
        var closed=new HashSet<Vector2Int>();
        var g=new Dictionary<Vector2Int,int>{{inicio,0}};
        var padre=new Dictionary<Vector2Int,Vector2Int>();
        var dirs=new[]{Vector2Int.right,Vector2Int.up,
                       Vector2Int.left,Vector2Int.down};
        while(open.Count>0) {
            int k=algoritmo=="DFS"?open.Count-1:0;
            if(algoritmo=="A*")
                for(int i=1;i<open.Count;i++)
                    if(g[open[i]]+H(open[i]) < g[open[k]]+H(open[k])) k=i;
            var n=open[k]; open.RemoveAt(k); closed.Add(n);
            if(n==meta) {
                ruta.Add(n);
                while(n!=inicio){n=padre[n];ruta.Add(n);}
                ruta.Reverse(); return ruta;
            }
            foreach(var d in dirs) {
                var v=n+d;
                if(!Valido(v)||closed.Contains(v)) continue;
                int nuevo=g[n]+1;
                if(g.ContainsKey(v) && (algoritmo!="A*"||nuevo>=g[v])) continue;
                g[v]=nuevo; padre[v]=n;
                if(!open.Contains(v)) open.Add(v);
            }
        }
        return ruta;
    }
}

Para BFS real a gran escala usa Queue<Vector2Int> y para DFS Stack<Vector2Int>. La lista común simplifica la comparación, pero RemoveAt(0) y la búsqueda lineal del mínimo son menos eficientes que estructuras especializadas.

Construir el laberinto y mostrar la ruta

// Dentro de un MonoBehaviour; origen es Vector3, celda es float.
Vector3 Centro(int x, int z) =>
    origen + new Vector3(x * celda, 0, z * celda);
// En el bucle de creación del laberinto, si hay muro:
float altura = 1f + 4f * Mathf.PerlinNoise(x * 0.12f, z * 0.12f);
GameObject muro = GameObject.CreatePrimitive(PrimitiveType.Cube);
muro.transform.position = Centro(x,z) + Vector3.up * altura/2f;
muro.transform.localScale = new Vector3(celda,altura,celda);

Perlin Noise modifica la altura de los muros, no obliga a modificar la conectividad ni el coste de los caminos. Si generas un terreno con pendientes transitables, puedes introducir costes adicionales y adaptar la heurística.

// Tras calcular ruta con BusquedaGrid.Buscar:
line.useWorldSpace = true;
line.positionCount = ruta.Count;
for(int i=0;i<ruta.Count;i++)
    line.SetPosition(i, Centro(ruta[i].x,ruta[i].y)+Vector3.up*0.1f);

Configura un LineRenderer con material y ancho visible. Para seleccionar casillas, lanza un raycast desde la cámara con ScreenPointToRay, convierte el impacto al grid usando el mismo origen y tamaño de celda, verifica límites y transitabilidad y alterna selección de origen y destino.

El ejemplo del enunciado usa ocho vecinos y costes 10/14. Si lo adaptas, evita cortar esquinas entre muros y usa la misma transformación mundo-grid en ambos sentidos. Reinicia costes y padres entre búsquedas. El ejemplo de este laboratorio usa cuatro vecinos deliberadamente.
